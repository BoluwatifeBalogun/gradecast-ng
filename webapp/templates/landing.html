From a student's details to a plan, in four steps

The whole run takes under a second. Nothing here replaces an examination. It tells you where to look first.

  1. Enter the details

    A student or academic officer fills in study habits, wellbeing, home background and school environment.

  2. Check and prepare

    Each value is validated, categories are encoded as numbers and numeric values are scaled the same way as the training data.

  3. Two models vote

    Random Forest and Gradient Boosting each estimate the chance of every class. A voting classifier combines them.

  4. Read the result

    You get the predicted class, the probability of each class, what is driving it and which changes would help most.

An ensemble, because one model on its own gets it wrong more often

The system follows the Knowledge Discovery in Databases process: select, clean, transform, mine, evaluate.

Two learners, one decision

Random Forest averages hundreds of independent trees. Gradient Boosting builds trees in sequence, each fixing the last one's mistakes. Soft voting blends their probabilities.

Balanced with SMOTE

Few students fail and few earn a First Class, so a model can ignore both. SMOTE creates synthetic neighbours for the rare classes until every class is the same size.

Questions people ask first

Where does the training data come from? {{ icon('plus') }}

The model is trained on the public Student Performance Factors dataset from Kaggle, which holds {{ '{:,}'.format(metrics.dataset.cleaning.rows_raw) if metrics else '6,607' }} student records. It is not a record of Nigerian students. An administrator can upload an institution's own data in the same format and retrain.

What do the five classes mean? {{ icon('plus') }}

Exam scores in the dataset sit in a narrow range, so they are banded relative to the cohort{% if metrics %}: Fail up to {{ metrics.cutoffs[0]|int }}, Pass {{ metrics.cutoffs[0]|int + 1 }} to {{ metrics.cutoffs[1]|int }}, Lower Second {{ metrics.cutoffs[1]|int + 1 }} to {{ metrics.cutoffs[2]|int }}, Upper Second {{ metrics.cutoffs[2]|int + 1 }} to {{ metrics.cutoffs[3]|int }}, and First Class above {{ metrics.cutoffs[3]|int }}{% endif %}. Read a class as the student's standing among peers, not as a CGPA.

Does a prediction decide a student's result? {{ icon('plus') }}

No. It is an early signal built from patterns in past data. Use it to start a conversation and offer support. Admission, grading and progression decisions should never rest on it alone.

How should I read the suggestions? {{ icon('plus') }}

For each attribute a student can change, the system asks the model what would happen if only that attribute improved. The suggestions show what the model is sensitive to. They are not proof that the change will cause the result.

Who can see the records I create? {{ icon('plus') }}

Only you and the system administrator. Students and academic officers each see their own predictions.
